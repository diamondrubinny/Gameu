# Gameu לטלוויזיה — אפליקציית Android TV / Google TV

> סטטוס: **אושר (23.10.2026). T1 ✅ · T2 ✅ · T3 ✅ · T4/T5 — הבא בתור**
> תאריך: 2026-10-23 · ענף: `diamond-rubinny`

## 1. מה נבנה
אפליקציה שמותקנת על הטלוויזיה עצמה (Android TV / Google TV), בלי מחשב, בלי USB למחשב ובלי שרת בענן:
- פותחים את האפליקציה מהשלט הרגיל ← מסך הקונסולה מופיע עם QR.
- הטלפונים סורקים ומתחברים **ישירות לטלוויזיה** דרך ה־Wi‑Fi הביתי.
- אותם משחקים, אותו שלט בטלפון ואותו מסך שכבר בנינו — בלי לשכתב אותם.

```
┌──────────── Android TV ────────────────────────┐
│  WebView (מסך הקונסולה + לוגיקת החדר ב־TS)      │
│        ▲ JS bridge (הודעות טקסט בלבד)           │
│  Kotlin: שרת HTTP + WebSocket על פורט 8080      │
└────────▲───────────────────────────────────────┘
         │ Wi‑Fi
   📱 📱 📱  השלט בדפדפן הטלפון (ללא שינוי)
```

## 2. החלטה ארכיטקטונית (המלצה: חלופה C)

| חלופה | תיאור | יתרונות | חסרונות |
|---|---|---|---|
| A. Node.js בתוך האפליקציה (nodejs-mobile) | מריצים את `server.cjs` כמו שהוא | כמעט אפס שינויי קוד | APK גדול (~40MB+), פרויקט קהילתי — תחזוקה וגרסת Node **דורשים אימות**, מנוע native נוסף לתחזק |
| B. שכתוב השרת ב־Kotlin | כל הלוגיקה ב־Kotlin | ביצועים, Native מלא | **שתי גרסאות** של לוגיקת חדר וולידציה — באגים כפולים |
| **C. ✅ שכבת תעבורה ב־Kotlin + לוגיקה ב־TypeScript** | Kotlin רק מקבל חיבורים ומעביר טקסט; החדר, הוולידציה (zod), הגבלות הקצב — אותו קוד TS שכבר נבדק, רץ בתוך ה־WebView | מקור אמת אחד ללוגיקה, APK קטן (~8–12MB), אותן בדיקות | צריך לשבור את השרת לליבה בלתי־תלויה ב־Node (refactor), JS bridge מוסיף השהיה זניחה (<1ms) |

**ספריית שרת ב־Kotlin:** Ktor Server (מנוע CIO) — מתוחזק, תומך WebSocket. חלופות: NanoHTTPD (לא מתוחזק מאז 2016), Java-WebSocket + שרת HTTP ידני. *התאמת Ktor Server ל־Android בגרסה שתיבחר — דורש אימות מול התיעוד הרשמי.*

## 3. שינויים בקוד הקיים (Refactor, תאימות לאחור מלאה)
1. `Room` + טיפול בהודעות שלט → מודול ליבה **ללא תלות ב־Node** (`src/core/`): קריפטו דרך ממשק (`node:crypto` בשרת, `crypto.getRandomValues` בטלוויזיה).
2. הוצאת הלוגיקה של `onController` מ־`app.ts` ל־`ControllerSession` משותף — השרת ב־Node והאפליקציה ישתמשו באותו קוד.
3. `HostConnection` → ממשק עם שני מימושים: WebSocket (מחשב/USB) ו־In-process (טלוויזיה — אין בכלל ערוץ host ברשת, **שיפור אבטחה**).
4. כל הבדיקות הקיימות (40 + 8 e2e) חייבות להמשיך לעבור.

## 4. האפליקציה (`android/`)
- Kotlin, Gradle Kotlin DSL, minSdk 26 (Android 8, רוב טלוויזיות Android TV מ־2018 ואילך), targetSdk עדכני.
- `Activity` אחת במסך מלא עם WebView; נכסים נטענים דרך `WebViewAssetLoader` (מקור https מאובטח, בלי גישה לקבצים).
- דרישות Android TV: `LEANBACK_LAUNCHER`, באנר 320×180, `touchscreen required=false`, ניווט D‑pad (כבר קיים), מקש Back של השלט.
- מסך דולק בזמן משחק (`FLAG_KEEP_SCREEN_ON`), השרת נעצר כשיוצאים מהאפליקציה.
- זיהוי כתובת IP של ה־Wi‑Fi/Ethernet לצורך ה־QR; הודעה ברורה אם אין רשת.
- הרשאות: `INTERNET`, `ACCESS_NETWORK_STATE` בלבד.

## 5. אבטחה, פרטיות ונגישות
- **מה משתפר:** ערוץ המסך כבר לא חשוף ברשת בכלל (in‑process).
- **מה נשמר:** בדיקות Origin/Host, CSP, הגבלת גודל הודעה (בשכבת Kotlin) והגבלת קצב (TS), משחקים ב־sandbox.
- **WebView:** JavaScript Bridge חשוף **רק** לדף המקומי (בדיקת origin), בלי `allowFileAccess`, בלי ניווט לאתרים חיצוניים.
- **פרטיות:** אין שינוי — אין איסוף, אין צד שלישי. אם תפורסם ב־Google Play: טופס Data Safety ("לא נאסף מידע") ומדיניות פרטיות עם URL ציבורי — **דורש בדיקה משפטית**.
- **נגישות:** TalkBack בטלוויזיה (WebView חושף את ה־ARIA הקיים) — בדיקה ידנית נדרשת.

## 6. התקנה על הטלוויזיה (Sideload — בלי Google Play)
1. בטלוויזיה: הגדרות ← מערכת ← אודות ← לחיצה 7 פעמים על "Android TV OS build" ← אפשרויות מפתחים.
2. התרת התקנה ממקורות לא ידועים לאפליקציית ניהול הקבצים.
3. העתקת `Gameu.apk` ל־USB ← חיבור לטלוויזיה ← פתיחה עם מנהל קבצים (למשל File Commander / X-plore) ← התקנה.
   חלופות: אפליקציית Downloader, או `adb install` מהמחשב.
4. Google Play — שלב מאוחר יותר (חשבון מפתח, חתימה, בדיקת איכות TV של Google).

> מסתדר עם הרעיון המקורי: **ה־APK מותקן מה־USB**.

## 8. סיכונים ומגבלות
1. **אין לי טלוויזיה או אמולטור כאן** — אבנה ואבדוק בנייה + בדיקות אוטומטיות, אבל הבדיקה האמיתית תהיה אצלך על הטלוויזיה.
2. **WebView ישן** בטלוויזיות לא מעודכנות — נבנה ליעד Chrome 70; אם ה־WebView ישן יותר נציג הודעה לעדכן "Android System WebView".
3. **ראוטר עם Client Isolation / רשת אורחים** — יחסום טלפון↔טלוויזיה (כמו במחשב).
4. **שינה של הטלוויזיה / חיסכון חשמל** — עלולים לנתק; מטופל ע"י Keep Screen On בזמן שהאפליקציה פתוחה.
5. Samsung/LG **לא** נתמכות באפליקציה הזו (מערכות הפעלה אחרות) — אצלן נשאר מצב "מחשב + דפדפן".

## 9. מה כבר עובד היום (בלי אפליקציה)
מצב "מחשב + דפדפן הטלוויזיה" נבדק: מריצים את Gameu על מחשב ברשת עם `GAMEU_HOST_KEY`, ופותחים בדפדפן הטלוויזיה `http://<IP>:8080/?key=<KEY>`. נוספה תמיכה במקשי Back של שלטי טלוויזיה.
