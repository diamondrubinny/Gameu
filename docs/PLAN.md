# Gameu — קונסולת משחקים מ־USB לכל טלוויזיה, עם הטלפון כשלט

> סטטוס: **שלבים 0–6 נבנו ונבדקו** (ראו "סטטוס ביצוע" בסוף). שלב 7 (Live USB) — הבא בתור.
> תאריך: 2026-10-23

---

## 1. סיכום ההבנה

מערכת שהופכת כל טלוויזיה לקונסולת משחקים:
- **המסך (Host)** — מציג תפריט משחקים ומריץ את המשחקים על הטלוויזיה.
- **השלט (Controller)** — הטלפון של כל שחקן הופך לג'ויסטיק/שלט, בלי התקנת אפליקציה (סורקים QR ונכנסים מהדפדפן).
- **הפצה מ־USB** — מכניסים דיסק־און־קי למחשב/מיני־PC שמחובר לטלוויזיה ב־HDMI, והמערכת עולה לבד.

### מגבלה טכנית שחשוב להבין מראש
טלוויזיה **לא יכולה להריץ מערכת הפעלה או תוכנה מדיסק־און־קי** — חיבור ה־USB בטלוויזיה (גם חכמה) מיועד לניגון מדיה בלבד.
לכן "USB על כל טלוויזיה" אפשרי בפועל בשלוש דרכים, והתוכנית תומכת בכולן מאותו קוד:

| מצב | מה צריך | איך זה עובד |
|---|---|---|
| **A. USB אתחול (Bootable)** | כל מחשב/לפטופ/מיני־PC (x86_64) + HDMI | מאתחלים מה־USB → לינוקס מינימלי עולה ישר למסך הקונסולה (Kiosk). המחשב המארח לא משתנה. |
| **B. USB נייד (Portable)** | לפטופ Windows/Mac/Linux מחובר לטלוויזיה | מריצים קובץ מה־USB בלי התקנה → נפתח מסך מלא. |
| **C. דפדפן הטלוויזיה / Chromecast / Fire TV** | טלוויזיה חכמה עם דפדפן, ושרת ברשת (מחשב עם USB מצב B, או ענן) | פותחים כתובת בדפדפן הטלוויזיה → מסך הקונסולה. |
| **D. (שלב מאוחר) Raspberry Pi / Android TV** | Pi 4/5 או APK | אותו Host, אריזה שונה. |

## 2. הנחות עבודה ושאלות הבהרה

### הנחות (אם לא תתקן — נמשיך לפיהן)
1. **משחקים:** משחקי HTML5 מקוריים שנפתח בעצמנו (Party games + ארקייד), בדומה ל־AirConsole/Jackbox. **לא** אמולטורים עם ROMים מסחריים (בעיית זכויות יוצרים).
2. **רשת:** עובדים ב־**LAN מקומי בלי אינטרנט** (הטלפונים מתחברים ל־Wi‑Fi הביתי, או ל־Hotspot שה־USB יוצר במצב A). ענן — אופציונלי בהמשך.
3. **שחקנים:** 1–8 טלפונים במקביל.
4. **שפה:** עברית RTL כברירת מחדל + אנגלית.
5. **שימוש:** ביתי/אישי ב־MVP, עם ארכיטקטורה שמאפשרת מסחור בהמשך.

### החלטות שהתקבלו (23.10.2026 — "תחליט אתה")
1. משחקים מקוריים בלבד (ללא אמולטורים/ROMים).
2. חומרה: כל לפטופ/מיני־PC (Windows/Mac/Linux, x64/arm64 כולל Raspberry Pi 64 ביט) מחובר ב־HDMI.
3. רשת: Wi‑Fi ביתי ב־MVP; Hotspot עצמאי — בשלב 7 (Live USB).
4. שימוש פרטי, ארכיטקטורה שמאפשרת מסחור.
5. מצב B (USB נייד) קודם — **בוצע**; מצב A בהמשך.

### שאלות (עד 5) — נענו למעלה
1. **אילו משחקים?** משחקים מקוריים בלבד, או שחשוב גם אמולציה של משחקים ישנים (למשל משחקים חופשיים/Homebrew שבבעלותך)?
2. **חומרה:** על מה תחבר בפועל — לפטופ ישן, מיני־PC, Raspberry Pi, או רק טלוויזיה חכמה?
3. **אינטרנט:** האם המערכת חייבת לעבוד גם בלי Wi‑Fi ביתי בכלל (Hotspot מה־USB)?
4. **מסחור:** זה מוצר למכירה (חנות משחקים, חשבונות משתמש, תשלומים) או לשימוש פרטי?
5. **עדיפות:** מה חשוב יותר ב־MVP — מצב A (USB אתחול) או מצב B (USB נייד לפטופ)? המלצתי: **B קודם** (מהיר, פחות סיכון), A מיד אחריו.

## 3. אפיון MVP

### מטרות MVP
- הפעלה מ־USB (מצב B) + פתיחה בדפדפן טלוויזיה (מצב C).
- חיבור טלפון ב־QR תוך פחות מ־10 שניות, בלי אפליקציה.
- תפריט קונסולה שנשלט מהטלפון (D‑pad + OK + Back).
- 3 משחקים לדוגמה: **טריוויה** (party), **Snake/פונג מרובה משתתפים** (ארקייד), **ציור וניחוש** (party).
- SDK פנימי פשוט להוספת משחקים חדשים.

### מחוץ ל־MVP
חשבונות משתמש, חנות, תשלומים, ענן, אמולטורים, Android TV, שמירת התקדמות בענן.

### User Stories
| # | כמשתמש… | אני רוצה… | כדי ש… |
|---|---|---|---|
| 1 | בעל הבית | לחבר USB ולראות מסך קונסולה על הטלוויזיה | לא אצטרך להתקין כלום |
| 2 | שחקן | לסרוק QR בטלפון ולהפוך אותו לשלט | אצטרף מיד |
| 3 | שחקן | לנווט בתפריט ולבחור משחק מהטלפון | לא אצטרך מקלדת/עכבר |
| 4 | שחקן | לבחור כינוי ואווטאר | יזהו אותי במסך |
| 5 | מארח | להיות "מנהל החדר" (בחירת משחק, הוצאת שחקן) | לשמור על סדר |
| 6 | שחקן | להתחבר מחדש אוטומטית אם הטלפון ננעל | לא אאבד את המקום במשחק |
| 7 | שחקן | רטט ומשוב בטלפון | להרגיש את המשחק |
| 8 | מפתח | להוסיף משחק כתיקייה עם manifest | להרחיב את הקונסולה בקלות |
| 9 | משתמש עם מוגבלות | ניגודיות גבוהה, טקסט גדול, הקראה | אוכל לשחק |

### מסכים וזרימות

**Host (טלוויזיה):**
1. Splash → 2. **Lobby**: QR גדול + קוד חדר 4 ספרות + כתובת IP + רשימת שחקנים מחוברים → 3. **תפריט משחקים** (גריד) → 4. **מסך משחק** → 5. **תוצאות** → חזרה לתפריט. + מסך הגדרות (שפה, נגישות, Wi‑Fi במצב A), הצהרת נגישות, מידע פרטיות.

**Controller (טלפון):**
1. כניסה מ־QR → 2. בחירת כינוי/אווטאר → 3. **שלט תפריט** (D‑pad, OK, Back, Home) → 4. **שלט משחק** — פריסה דינמית שהמשחק מגדיר (כפתורים / ג'ויסטיק / טקסט / ציור / תשובות) → 5. מצב ניתוק/התחברות מחדש.

**זרימת חיבור:**
```
Host עולה → שרת מקומי מאזין על :8080 → נוצר חדר + Token
טלפון סורק QR (http://192.168.x.x:8080/c?room=1234&t=…)
→ WebSocket → join(nickname) → Host מקבל player_joined
→ קלט מהטלפון → שרת → Host (ותצוגת state בחזרה לטלפון)
```

## 4. ארכיטקטורה

```
┌──────────────── USB ─────────────────┐
│  Gameu Runtime                        │
│  ┌──────────────┐   ┌──────────────┐  │        Wi‑Fi / LAN
│  │ Node.js Server│◄─►│ Host UI      │──┼──HDMI──► 📺 TV
│  │ HTTP + WS     │   │ (Chromium    │  │
│  │ rooms, relay  │   │  kiosk)      │  │
│  └──────▲───────┘   └──────────────┘  │
└─────────┼─────────────────────────────┘
          │ WebSocket (JSON, ולידציה)
   📱 📱 📱  Controller PWA (דפדפן הטלפון)
```

### רכיבים
1. **server** (Node.js + TypeScript): מגיש קבצים סטטיים, מנהל חדרים, מעביר הודעות בין Host לבקרים, ולידציה ו־Rate limit. **לא שומר מידע אישי לדיסק.**
2. **host** (Web app, TypeScript): תפריט, Lobby, טוען משחקים ב־`iframe` מבודד (sandbox) ומעביר אליהם קלט דרך `postMessage`.
3. **controller** (PWA, TypeScript): שלט דינמי, רטט (`navigator.vibrate`), מסך מלא, Wake Lock, התחברות מחדש.
4. **shared**: טיפוסים ופרוטוקול + סכמות Zod משותפות לשרת ולקליינט.
5. **sdk**: ספרייה קטנה למשחקים: `onInput`, `setControllerLayout`, `sendToPlayer`, `endGame`.
6. **games/**: כל משחק תיקייה עם `manifest.json` + `index.html`.
7. **packaging**:
   - מצב B: בינארי יחיד לכל OS (Node SEA / `pkg`‑like) + Chromium/דפדפן קיים במצב `--kiosk`. *(דורש אימות מול התיעוד הרשמי של Node SEA בגרסה שתיבחר.)*
   - מצב A: אימג' לינוקס (Debian live מינימלי דרך `live-build`) עם Cage/X + Chromium kiosk + שירות systemd לשרת + Hotspot אופציונלי (NetworkManager). קובץ `.img` נצרב ל־USB עם balenaEtcher/Rufus.

### פרוטוקול (דוגמה)
```ts
// Controller → Server
{ type: "join", room: "1234", token: string, nickname: string, avatar: number }
{ type: "input", kind: "button", id: "A", pressed: true }
{ type: "input", kind: "stick", x: -0.4, y: 0.9 }
{ type: "input", kind: "text", value: string }      // מוגבל באורך
// Server → Host
{ type: "player_joined", playerId, nickname, avatar }
{ type: "player_input", playerId, input }
// Host → Controller
{ type: "layout", layout: ControllerLayout }        // איזה שלט להציג
{ type: "haptic", pattern: number[] }
```

### מודל נתונים (בזיכרון בלבד ב־MVP)
```ts
Room   { id, code(4), hostSocket, adminPlayerId, players: Map, currentGame?, createdAt }
Player { id(uuid), nickname(≤16), avatar(0‑11), reconnectToken, connected, lastSeen }
Game   { id, name, minPlayers, maxPlayers, controllerType, entry }
Settings (קובץ JSON מקומי ב־USB): { language, highContrast, textScale, reduceMotion, volume }
```
אין בסיס נתונים ב־MVP. אם יידרש בהמשך (פרופילים, שיאים) — SQLite מקומי על ה־USB.

## 6. אבטחה, פרטיות, עוגיות ונגישות

### Threat Model קצר
| נכס | איום | סיכון | בקרה |
|---|---|---|---|
| שליטה במסך | שכן ברשת מתחבר ומשתלט | בינוני | קוד חדר + join token ב־QR, אישור שחקן ע"י מנהל החדר, נעילת חדר |
| ערוץ Host | התחזות למסך | גבוה | `/ws/host` רק מ־localhost + secret אקראי בכל הפעלה |
| השרת | הצפת הודעות / DoS מקומי | בינוני | Rate limit לכל socket, payload ≤ 4KB, מקס' 8 שחקנים, ניתוק על הודעה לא תקינה |
| קלט טקסט (כינוי/תשובות/צ'אט) | XSS על המסך | גבוה | ולידציית Zod, אורך מקסימלי, הצגה כ־`textContent` בלבד, CSP קשיח |
| משחקים | משחק זדוני ניגש למערכת | בינוני | `iframe sandbox="allow-scripts"` בלי `allow-same-origin`, CSP, רק משחקים חתומים/מקומיים |
| Hotspot (מצב A) | גישה לרשת | נמוך‑בינוני | WPA2/3 עם סיסמה אקראית שמוצגת על המסך, בידוד — אין ניתוב לאינטרנט |
| ה־USB | שינוי קבצים | נמוך | מערכת קבצים read‑only (squashfs) במצב A, checksum לאימג' |

**תעבורה:** ב־LAN מקומי ללא אינטרנט, HTTPS דורש תעודה שהטלפון לא סומך עליה — לכן MVP עובד ב־HTTP **רק ב־LAN** עם Token. מצב ענן (אם יהיה) — HTTPS/WSS בלבד. *החלטה פתוחה לאישורך.*
כותרות: CSP, `X-Frame-Options`/`frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`.
אין העלאת קבצים ב־MVP (ציורים נשלחים כקואורדינטות, לא כקבצים).

### פרטיות
- **Data Map:** כינוי + אווטאר — מקור: שחקן; מטרה: תצוגה במשחק; אחסון: זיכרון RAM בלבד; זמן שמירה: עד סגירת החדר; צד שלישי: אין. כתובת IP — בזיכרון בלבד לצורך החיבור, לא נרשמת ללוג.
- אין חשבונות, אין Analytics, אין פיקסלים, אין שליחת מידע החוצה.
- שחקנים קטינים צפויים (קונסולה משפחתית) → **לא אוספים שם אמיתי**, הסבר במסך: "השתמשו בכינוי, לא בשם מלא". כל מעבר למסחור/ענן — **דורש בדיקה משפטית** (חוק הגנת הפרטיות ותיקון 13, GDPR, קטינים).

### עוגיות
- MVP: **ללא עוגיות**. `localStorage` בטלפון לשמירת כינוי ו־reconnectToken בלבד (חיוני לתפקוד, מוסבר בעמוד פרטיות). אין trackers → אין צורך בבאנר הסכמה. אם יתווספו Analytics — באנר הסכמה מלא לפי ההנחיות.

### נגישות
- RTL מלא, HTML סמנטי, יעד WCAG 2.1 AA ות"י 5568 (דורש בדיקה מקצועית).
- ממשק טלוויזיה ("10‑foot UI"): טקסט גדול, Focus בולט מאוד, ניגודיות גבוהה, ניווט D‑pad + מקלדת.
- בקר בטלפון: כפתורים ≥ 48px, `aria-label` לכל כפתור, מצב יד שמאל, אפשרות לביטול רטט.
- הגדרות: גודל טקסט, ניגודיות גבוהה, הפחתת תנועה (`prefers-reduced-motion`), כתוביות לכל צליל משמעותי.
- כל משחק מצהיר ב־manifest על תמיכה בנגישות; טריוויה כוללת זמן מורחב.
- עמוד הצהרת נגישות (טיוטה).

## 7. סיכונים ומגבלות
1. **"כל טלוויזיה"** — מחייב מחשב/מיני־PC או דפדפן בטלוויזיה; אין דרך להריץ קוד מ־USB ישירות בטלוויזיה.
2. **אתחול מ־USB** — Secure Boot, BIOS שונים, דרייברי Wi‑Fi — דורש בדיקות על חומרה אמיתית.
3. **רשתות אורחים / Client Isolation** בראוטרים חוסמים תקשורת טלפון↔מחשב — לכן מצב Hotspot חשוב.
4. **iOS** — אין Vibration API; מסך מלא מוגבל ב־Safari.
5. **דפדפני טלוויזיה ישנים** — תמיכה חלקית ב־JS מודרני; נבנה עם יעד ES2017 ונבדוק על Tizen/webOS.
6. **זכויות יוצרים** — אמולטורים/ROMים מסחריים מחוץ לתחום; כל אמולציה עתידית — **דורש בדיקה משפטית**.
